# Step 1: flat map, flying camera, debug menu — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A flat square map you fly over, with a draggable Esc debug menu (tabs → sections → setting rows) controlling map size and cell size, each with debug lines.

**Architecture:** A settings list (data) feeds a settings store (values, debug flags, change events, localStorage). A menu built from small DOM pieces renders the list and writes to the store. The world, renderer and camera only listen to the store. The ground is one flat quad; the cell grid is a shader pattern, so cell count costs nothing to draw.

**Tech Stack:** TypeScript 7, Vite 8.3, Three.js 0.187, Vitest 5 with happy-dom 21 for DOM tests.

**Spec:** `plans/2026-10-31-step1-design.md`

## Global Constraints

- Work on `main`. Per task: run only that area's tests (`npx vitest run tests/<area>`), commit. At the end: build into `docs/`, push, report done. No live-site check.
- Vite: `base: './'`, `outDir: 'docs'`, `emptyOutDir: true`, dev port 5174 (`strictPort`).
- Map size slider 100–4000 m, step 50, default 1000. Cell size slider 0.25–20 m, step 0.25, default 1.
- Cells per side = `Math.ceil(mapSize / cellSize)`; real size = cells × cellSize.
- Top-level tabs, in order: MAP, RIDER, BIKE, AI. MAP has section "Terrain".
- Row layout: debug checkbox → name label → control (slider + number box) → reset button; optional note.
- Esc toggles the menu. Game never pauses. Menu open: pointer unlocked. Menu closed: mouse look via pointer lock.
- Camera keys: WASD move, Space up, C down, Shift faster. Keys ignored while focus is in a text/number field.
- Plain sky, one sun, plain ground colour. Small files, one job each.

## Review Focus

1. **Esc while the pointer is locked** — the browser swallows that Esc and only releases the lock; the menu must still open (listen for `pointerlockchange`). Test in Task 5.
2. **Garbage or out-of-range typed into a number box** ("abc", "-5", "99999") — value clamps to min/max or reverts on blur; never NaN in the store. Tests in Tasks 2 and 4.
3. **Broken or outdated saved data** (invalid JSON, unknown ids, values out of range) — defaults/clamped values, no crash. Test in Task 2.
4. **Browser window shrunk after the menu was dragged near an edge** — menu is pulled back so its title bar stays reachable. Test in Task 4.
5. **Window loses focus while a movement key is held** — camera stops instead of flying forever (clear keys on `blur`). Test in Task 5.

## Decisions not in the spec

- Both debug checkboxes start ticked, so the first view shows the outline and grid.
- Heights grid: the spec says the ground is stored as heights. At 4000 m with 0.25 m cells that is 16,000² ≈ 256 M numbers (1 GB), which the browser can't hold. Step 1 stores only the grid description (`cells`, `cellSize`, `size`) plus `heightAt(x, z)` returning 0; the spline step chooses the height storage when we know how detailed it must be. (Flagged to the user.)

### Task 6: Ground drawing and debug lines, wired together

**Files:**
- Create: `src/render/groundView.ts`, `src/render/gridMaterial.ts`, `src/render/edgeOutline.ts`, `src/render/label.ts`
- Modify: `src/main.ts`

**Interfaces:**
- Consumes: `Ground`, `makeGround` (Task 3); `SettingsStore`, `SETTINGS`, `TABS` (Task 2); `buildMenu` (Task 4); `Input`, `FlyCamera`, `connectMenuAndMouse` (Task 5).
- Produces:
  - `gridMaterial.ts`: `makeGridMaterial(): ShaderMaterial` with uniforms `groundColor` (`#7a8b52`), `lineColor` (white), `cellSize`, `showGrid` (0/1), `sunDir`, `fadeDistance`. Fragment: world-space `coord = worldXZ / cellSize`, anti-aliased lines via `fwidth`; line strength × `1 − smoothstep(0.25, 0.5, max(fwidth(coord)))` so lines vanish before cells shrink below ~2 px; also × distance fade. Simple lambert from `sunDir` + ambient. Unit for distance fade: `fadeDistance = 60 × cellSize` clamped to [150, 3000] m.
  - `label.ts`: `makeLabel(text: string): Sprite` — canvas-texture sprite, `sizeAttenuation: false`, `depthTest: false`, `renderOrder: 10`, ~0.04 screen height; `setLabelText(s: Sprite, text: string): void`.
  - `edgeOutline.ts`: `class EdgeOutline { constructor(scene: Scene); update(size: number): void; visible: boolean }` — square `LineLoop` 0.05 m above ground, colour `#ffcc33`, `depthTest: false`, `renderOrder: 9`; four labels at side midpoints with text `"${size.toLocaleString('en-US')} m"`.
  - `groundView.ts`: `class GroundView { constructor(scene: Scene); update(ground: Ground, showGrid: boolean): void }` — one `PlaneGeometry(1,1)` mesh rotated flat, scaled to `ground.size`; sets `cellSize`/`showGrid` uniforms; one grid label at the map's middle edge-inset: `"${cellSize} m cells · ${cells} × ${cells}"`, visible with the grid.
- `main.ts` wiring: store with `localStorage`; `buildMenu` into `#ui`, menu starts closed; on `mapSize`/`cellSize` change → `makeGround`, `groundView.update`, `edgeOutline.update`, row notes `"real size ${size.toLocaleString('en-US')} m · ${cells.toLocaleString('en-US')} cells"` (on both rows); debug flag changes toggle outline / grid; `connectMenuAndMouse`; each frame `flyCamera.update(dt, input, !!document.pointerLockElement)`; `placeOverCorner(store.get('mapSize'))` once at start.
